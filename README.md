# Project Map Orchestrator · pmap

Локальная карта проекта и оркестратор Codex: задачи, решения, параллельные исполнители, проверки результатов и поиск по исходникам.

## Быстрый запуск после клонирования

Нужен Python 3.11+. Для исполнителей нужен установленный Codex; для семантического поиска — Ollama с моделью embeddinggemma. Node.js нужен для JavaScript-тестов.

```powershell
git clone https://github.com/DIBERLOG/project-map-orchestrator.git
cd project-map-orchestrator
python launch.py
```

Откроется http://127.0.0.1:4317/. Подключите папку проекта через интерфейс. База и журналы создаются локально и не входят в репозиторий. На Windows команда `powershell -File install_startup.ps1` устанавливает ярлыки запуска и автозагрузки; `python install_capture.py` подключает обработчики событий Codex, которым требуется штатное доверие клиента.

Ниже сохранены сведения о разработке и проверках на исходном компьютере. Установленные там модели, ярлыки и настройки нужно настроить отдельно на новом компьютере.

## Запуск без терминала

Открой ярлык **pmap** на рабочем столе: он запускает локальный сервер, дожидается ответа и открывает карту. Повторное открытие использует уже работающий сервер. Адрес: http://127.0.0.1:4317/.

Установлен ярлык **pmap-autostart** в автозагрузке Windows: после входа в систему сервер запускается скрыто, без открытия браузера. Сам вход после перезагрузки ещё не проверялся. Восстановить оба ярлыка: `powershell -File install_startup.ps1`. Ручной запуск: `python launch.py`; только сервер: `python launch.py --no-browser`. Если порт занят чужой программой, запуск сообщает об ошибке и не останавливает её. Журналы находятся в `outputs/server-launch.log` и `outputs/launcher-error.log`.

Веб-версия общая для всех зарегистрированных папок: выбери проект в левом списке или нажми «Подключить папку». `$pmap` в другом чате включает сопровождение текущего проекта; это не команда браузера.

## Отложить или отменить

В карточке узла доступны «Отложить», «Отменить задачу» и «Вернуть в план». Выбор сохраняет содержимое формы и историю. Новые состояния `deferred` и `cancelled` доступны через MCP; агенту достаточно просьбы отменить/отложить конкретную задачу. При неоднозначности агент уточняет цель и не меняет остальные задачи.

Такие задачи не запускаются. Ожидающий запуск снимается с очереди, активный получает запрос остановки. Завершение исполнителя и повторная отправка плана не отменяют пользовательский выбор. Файлы и история не удаляются. Возобновление требует явного возврата в план и новой постановки в очередь. Перезагрузите подключение MCP/чат, чтобы процесс сервера инструментов загрузил обновлённые статусы.

Полосы прокрутки карты, боковой панели, редактора и журналов получили контрастную дорожку и ползунок. На системах с принудительным автоскрытием полос их видимость также зависит от настроек ОС/браузера.

Применение требует актуального прогона, чистой исходной папки и неизменного HEAD; изменения помещаются в Git index без коммита и публикации. Проверены комбинация двух результатов, конфликт, новые файлы, защита пользовательского черновика и применение. Реальный результат Codex также собран и проверен: `outputs/codex-smoke/integration-result.json`. Git на Windows может преобразовать LF/CRLF; проверки текстового содержимого учитывают это.

Семантический поиск: раздел **Знания проекта** → «По смыслу». Используется локальная Ollama `embeddinggemma` (768 измерений). Модель уже загружена на этот компьютер. Векторы кэшируются по содержимому, удалённые файлы исключаются из выдачи. Реальный тест на русском нашёл инструкцию восстановления пароля по запросу о забытых данных для входа; повторный поиск использовал кэш. Отчёт: `outputs/semantic-smoke.json`. Это RAG-извлечение: найденные фрагменты предоставляются агенту инструментом `map_semantic_search`; самостоятельная генерация ответа отдельной моделью не выполняется. При ручной замене версии embeddinggemma очистите таблицу `embeddings`, чтобы не смешивать векторы разных версий.

Автосбор: глобальный `~/.codex/hooks.json` зарегистрирован командой `python install_capture.py`. Сохраняются только чаты зарегистрированных проектов, запросы, пункты `update_plan`, события apply_patch и изменения Git-состояния на границах инструментов. Конец хода — событие, а не доказательство успеха. Повторы подавляются. Неотслеживаемые файлы проверяются до 5000 записей; для файлов свыше 2 МБ используются размер и время. Изменения игнорируемых Git файлов и правки без следующего события не гарантируются. Тексты запросов сохраняются локально; не отправляйте секреты.

Доставка `UserPromptSubmit`, `PostToolUse` и `Stop` из текущего реального чата подтверждена записями `hook_events`. Для другого клиента требуется штатное доверие точным обработчикам; обход доверия не используется. Это не доказательство охвата каждого чата. Служебный блок браузера исключается из текста нового запроса, исходный идентификатор защищает от дублей.

Сервер теперь запускает координатор очереди вместе с интерфейсом. Команда настройки штатного исполнителя: `python app.py worker-codex PROJECT_ID`. Уже настроен проект разработки pmap. Создание рабочих копий требует чистой сохранённой версии Git. Начальных коммитов в пользовательском проекте автоматически не создаём. Команда `coordinate` остаётся для отдельного запуска; блокировка не допускает второй экземпляр.

Удалённые PR/CI/staging по выбору пользователя остаются выключенными. Новые инструменты MCP появляются после обновления подключения/перезапуска чата. Нижние разделы содержат историю первой настройки; текущий статус выше имеет приоритет.

# Project Map · локальный оркестратор

## Очередь исполнителей

Добавлен локальный координатор `python app.py coordinate`. Он запускает **только заранее настроенную команду**, передавая краткое задание через stdin. Для задачи нужны критерии, относительные пути области работы через запятую и созданная рабочая копия. Кнопка «В очередь исполнителя» ставит её в очередь; раздел «Исполнители» показывает результаты и позволяет запросить остановку.

Настройка: `python app.py worker-config PROJECT_ID --parallel 2 --timeout 600 --command-json '["EXECUTABLE", "ARGUMENT"]'`. Для Codex используйте полный путь к исполняемому файлу CLI, поддерживающему `exec`, и аргументы `exec`, `--json`, `--sandbox`, `workspace-write`, `-`. При несовместимости локального CLI с конфигурацией сначала устраните её; очередь честно покажет ошибку запуска. Не используйте обход разрешений. Команда может расходовать лимиты модели; модель и тариф выбираются вашей конфигурацией.

Максимум 1–4 процесса **на проект**, тайм-аут до 3600 секунд. Задачи с пересечением областей файлов не выполняются одновременно. Зависимости ждут статуса `done`. При изменении требований уже поставленный запуск становится `stale`. Успех процесса переводит задачу только в `review`; для приёмки нужны отдельные проверки. Область файлов проверяется после выполнения через Git: это обнаружение нарушений, а не запрет доступа к другим файлам. Объединение рабочих копий доступно в отдельном разделе и требует явного применения после проверки.

Координатор единственный для базы (блокировка ОС). При штатной остановке он останавливает свои процессы. После аварии старые запуски помечаются `orphaned`, остаются блокирующими и не перезапускаются автоматически. «Проверить восстановление» требует, чтобы сохранённый PID больше не существовал. Если PID отсутствует или дерево процессов нельзя проверить, нужна ручная проверка. Рабочие копии сохраняются. Вывод ограничен 24 КБ; usage отображается только если итоговое событие Codex попало в сохранённый вывод. Денежный или точный токенный бюджет пока не обеспечивается.

Проверены тестовыми процессами: очередь, изоляция копий, пересечения, зависимости, отмена, тайм-аут и отказ при выходе за область. Реальный модельный запуск через Codex настольного приложения и доставка hooks из текущего чата проверены.

## Знания и экспорт

Перед экспортом выберите формат рядом с кнопкой: **JSON · полный архив** или **Markdown · узлы**. Каждый щелчок скачивает один файл, чтобы браузер не блокировал второе скачивание. JSON включает события, задания и интеграции; Markdown — читаемый список узлов с критериями и доказательствами.

Поиск показывает ожидание, блокирует повторную отправку и позволяет повтор после ошибки, сохраняя запрос. Ответ предыдущего проекта не вставляется в другой экран. Если установленная Ollama не запущена, поиск по смыслу запускает её локально по требованию; модели автоматически не скачиваются. При отсутствии Ollama доступен поиск по словам. Журнал запуска — `outputs/ollama-server.log`.

## Задача относится к исходникам другого проекта

В редакторе существующего узла поле **Проверять в проекте** выбирает зарегистрированный проект, чью команду и папку исходников проверять. По умолчанию проверяется текущий проект. Это полезно для старых задач pmap, записанных в карте Jarvis: выберите «Project Map · наша разработка», сохраните, откройте узел заново и запустите проверку. История и результат остаются в карте Jarvis.

Через MCP задайте `check_project` в `map_update_node`; пустая строка возвращает проверку в текущий проект. Смена назначения, runner или исходников требует нового прогона. Для отдельной рабочей копии всегда используется её собственный проект: внешний проект проверки с ней несовместим. Выбор проекта проверки не меняет папку или команду исполнителя. После обновления обновите подключение MCP, чтобы инструмент принял новое поле.

Раздел «Знания проекта» ищет актуальные фрагменты файлов и возвращает путь/строку. `map_retrieve` ищет по словам, `map_semantic_search` — по смыслу через локальные embeddings (подробнее выше). `map_code_graph` извлекает Python-функции и синтаксические вызовы через AST; динамическое разрешение связей и другие языки не поддерживаются. Повреждённые Python-файлы перечисляются отдельно.

Экспорт JSON через `/api/archive?project=ID` теперь включает всю историю, все тестовые прогоны и все задания исполнителей данного проекта. Снимок экрана по-прежнему ограничен последними событиями для скорости. Импорт резервной копии ещё не реализован.

Подготовлен `.github/workflows/check.yml` для Linux и Windows. В удалённом GitHub он не запускался: у проекта пока нет выбранного удалённого репозитория. Защита main, PR, staging и выпуск остаются ненастроенными.

## Короткий запуск pmap

`python package_local.py` регистрирует `pmap` в персональном каталоге `~/.agents/plugins/marketplace.json`, сохраняя существующие записи. Пакет находится в `~/.codex/plugins/pmap` и использует уже подключённый глобальный MCP `project-map`. Он не запускает второй сервер и не создаёт другую базу.

Плагин установлен штатной командой совместимого Codex `plugin add pmap@personal-local --json`. Проверка `plugin list --marketplace personal-local --json` подтвердила `installed: true` и `enabled: true`; копия находится в `~/.codex/plugins/cache/personal-local/pmap/0.1.0`. Для повторной установки используйте эти команды в актуальном Codex. Затем обновите/перезапустите настольный клиент и в чате проекта наберите `@pmap`, выбрав плагин в подсказках. Сам выбор в подсказках ещё не проверен. Просто текст `@pmap` без выбора не доказывает активацию.

Также установлен короткий навык `$pmap`: после обновления списка навыков его можно вызвать одним словом. Он выбирает текущую папку, регистрирует проект при отсутствии и читает карту. Дополнительная длинная инструкция не требуется. Это включает отслеживание текущего разговора агентом, но не автоматическую подписку на все чаты.

Карта, очередь, документы и история используют одну SQLite-базу. **Задача или исправление автоматически появляются в карте при создании через MCP или интерфейс.** Сохранённое изменение автоматически попадает в журнал. Правки в сторонних чатах и редакторах сами по себе пока не перехватываются.

## Настройка настоящих проверок

Узнайте ID проекта через `python app.py list`. Зарегистрируйте команду, подходящую этому проекту:

```powershell
python app.py runner PROJECT_ID -- python -m unittest discover -s tests -v
```

Команда запускается в папке проекта или в рабочей копии выбранной задачи. Она может менять файлы: настройка команды — доверенная локальная операция. Интерфейс не принимает произвольные команды. Лимит прогона 60 секунд, журнал ограничен последними 24 КБ. В первой версии выполняется только один прогон на проект.

Для принятия задачи/исправления нужны критерии, описание результата и последний успешный прогон с тем же отпечатком исходников. Отпечаток исключает `.git`, `data`, `outputs`, `node_modules`, `.venv`, `.worktrees`, кэши Python и журналы. Это ограничение первой версии: зависимости, окружение и файлы в исключённых каталогах не покрываются отпечатком; их изменения требуют отдельной перепроверки. Не используйте эти исключённые папки для исходного кода.

Если сервер был аварийно закрыт во время проверки, запись может остаться `running`. Не считайте её успехом. Восстановление прерванных прогонов — следующий этап; завершение старого процесса нужно проверить вручную.

## Ветки

«Создать ветку» использует `git worktree` и имя `codex/map-ID`. Нужен чистый Git-репозиторий с исходным коммитом. Создание коммитов, push, merge и публикация автоматически не выполняются. Рабочие копии находятся рядом с базой в `data/worktrees`.

## Данные и резервное копирование

База: `data/map.sqlite3`. Экспорт выдаёт JSON со снимком и Markdown с документами (последние 300 событий и 50 прогонов; это не полная резервная копия истории). Для полного копирования остановите сервер и MCP-процессы и скопируйте папку `data`. Не храните секреты в описаниях или тестовых журналах. Поиск — обычный поиск текста, не RAG. График отражает события, не расход токенов.

## Проверки разработки

```powershell
python -m unittest discover -s tests -v
node --check web/app.js
```

Тесты используют временные каталоги, включая отдельный Git-репозиторий. Проверяются сохранение, конфликты, зависимости, приёмка, прогоны, HTTP-границы, MCP stdio и worktree.

Полный план и границы: [SPEC.md](SPEC.md). Удалённый репозиторий, CI, protected main, staging, автономные исполнители, RAG и code graph пока не настроены. Их включение требует следующих этапов, а не переименования текущей версии в готовый оркестратор.
