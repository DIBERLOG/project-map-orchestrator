# Codex Project Map

## Назначение
Локальная карта проекта, единая история запросов, решений, задач, исправлений и проверок. Любая задача и исправление, созданные через интерфейс или MCP, автоматически являются узлом карты. Отдельно вести список задач и рисовать карту не нужно.

## Первая поставка
- Несколько проектов, локальная SQLite-база, атомарное сохранение события и узла.
- Типы: запрос, цель, вопрос, решение, спецификация, инструкция, задача, исправление, тест.
- Связи родитель–потомок и зависимости. Циклические зависимости запрещены.
- Карта, очередь задач, журнал и график событий; поиск; экспорт JSON и Markdown.
- Оптимистическая блокировка: устаревший редактор не перезаписывает изменения другого агента.
- Сжатый контекст для агента; MCP stdio без платных вызовов модели.
- Обработчик автоматических событий запросов и apply_patch с защитой от дублей; подключение к реальному клиенту требует проверки и штатного доверия hooks.
- Локальные Git worktrees по запросу. Настройка тестовой команды через CLI; реальные прогоны с журналом и отпечатком исходников.
- Задачи и исправления принимаются только при наличии критериев, описания результата и успешного актуального прогона.

## Критерии приёмки
1. Созданный через MCP запрос/задача/исправление появляется в карте после обновления (опрос раз в 3 секунды).
2. После перезапуска сервера сохраняются проекты, узлы, связи, события и прогоны.
3. Ошибка сохранения не стирает введённый текст. Конкурентное изменение возвращает конфликт.
4. Зависимости другой карты, циклы и запуск до завершения предпосылок отклоняются.
5. Заявление агента об успехе не подменяет реальный тестовый прогон.
6. HTTP доступен только на loopback, отклоняет посторонние Origin/Host и не позволяет произвольный запуск команд из браузера.
7. Проверки работают на временных данных и не меняют пользовательские проекты.

Задача без отдельной рабочей копии может явно выбрать другой зарегистрированный `check_project`. Тогда используются его заранее настроенная команда, папка и отпечаток; контракт включает назначение проверки. Прогоны и история остаются в исходном проекте задачи. Это не разрешает произвольную команду из браузера. Изменённая привязка, команда или исходники блокируют приёмку по старому прогону.

## Оставшиеся ограничения
- Hooks работают только в зарегистрированных проектах и поддерживающем их доверенном клиенте. Доставка событий текущего чата проверена; универсальный охват всех чатов и редакторов не гарантируется.
- Параллельные исполнители, отмена, восстановление и интеграционная приёмка реализованы локально. Токенный бюджет проекта проверяется перед каждым запуском по usage из отчётов исполнителя; идущий запуск может его превысить. Денежный бюджет не обеспечивается.
- Создание PR, CI, staging и protected main: после выбора удалённого репозитория и среды. Публикация не выполняется автоматически.
- Семантическое извлечение использует локальную Ollama embeddinggemma; граф кода ограничен Python AST, без разрешения динамических связей.

## Добавлено 29 октября: локальная очередь и знания
- Координатор с блокировкой единственного экземпляра, 1–4 процесса на проект, отмена и тайм-аут.
- Только заранее настроенный исполнитель; вход — краткое задание, выход — проверяемый журнал, `review` вместо автоматического `done`.
- Пересекающиеся области файлов ждут; выход за область обнаруживается после выполнения. Это не граница авторизации.
- Сбой сохраняет очередь и копии. Потерянные процессы блокируют повтор до проверки; автоматического возобновления неизвестного процесса нет.
- Поиск по актуальным фрагментам исходников и Python AST-граф (без разрешения runtime-связей). Полный JSON-архив событий/прогонов/заданий.
- CI workflow подготовлен в исходниках; удалённый запуск, staging и protected main не настроены по выбору «пока локально». Интеграция веток проверяется в отдельной рабочей копии, применение явно запрашивается пользователем и не создаёт коммит.
- Проверены настоящие локальные процессы-фикстуры и Codex настольного приложения: изменение файла, интеграционная проверка и применение в одноразовом репозитории. Отчёты — outputs/codex-smoke/. Токены доступны только из полученного usage, точный бюджет расходов не реализован.

## Удобный запуск и живая проверка
- launch.py переиспользует готовый сервер, ожидает его готовность и открывает браузер. Ярлык pmap запускает его без терминала; автозагрузка Windows запускает сервер без браузера.
- Через управление браузером проверены переключение проекта, сворачивание и раскрытие, масштаб, кривые связи, перетаскивание фона, создание и поиск узла, сохранение полей и статусы отложено/отменено. Продолжается проверка остальных разделов и узкого экрана; весь интерфейс пока не объявляется принятым.

## Добавлено 1 ноября: цепочки промтов и обслуживание
- Цепочка промтов: вставленный список сохраняется одной транзакцией как упорядоченная ветка узлов kind=prompt. Статусы шагов: Не завершено / Проверить / Завершено. Шаг в review или done делает следующий текущим; заголовок цепочки отражает общий итог.
- Hooks Codex продвигают цепочку: отправка текста текущего шага отмечает его, Stop переводит в review. Шаг засчитывается только при совпадении текста; очередь не перескакивается. Review не означает принятия результата.
- Прерванные проверки освобождаются по PID владельца и никогда не считаются успехом.
- Импорт JSON-архива как нового проекта, атомарно, без восстановления локальных команд и рабочих копий.
- Удаление зависимостей, рабочих копий и сборок с защитой несохранённых изменений и веток с коммитами.

## Правила
Не сохранять секреты и полный поток рассуждений. Хранить задачи, краткие решения и проверяемые результаты. Не объявлять карту полной, если источник событий не подключён. Состояние `done` означает проверку зарегистрированной командой и явно записанный результат, а не универсальную гарантию качества.
